M5 — Admin
The back of house
Members, instruments and service tokens. It has its own shell today — a separate header, its own pill nav, its own sign-out — which is why it looks like a different product: cards with headings, bordered tables, mono email addresses, badges for everything. Both directions put admin inside the member shell, now that Admin is a nav item: the same sidebar, the same page title, the sections as a row of pills under it. What differs is the ROSTER — the one screen that is genuinely a list of records rather than a list of things you listen to. Instruments and tokens follow whichever wins.
A1 — A real table
The table, kept — but as a grid of hairline rows with small-caps column heads, the same vocabulary the event ledger uses. Admin work IS tabular: you scan a column to find the one member whose status is wrong. The add form becomes one inline row of pill fields instead of a card with its own heading. On a phone the heads drop and each row stacks.

A2 — Rows, like everywhere else
No table at all — the member row becomes a row like every other row in the app: an initials disc, the name in the display face, email and status on a subline, one action. Reads better on a phone and matches the rest of the system, at the cost of the thing a table is actually good at: comparing one field down a list.
