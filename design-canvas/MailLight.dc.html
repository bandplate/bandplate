M2 — Text first, with a plain light HTML part

The text part stays the real message. Alongside it, one column on white: the wordmark, one sentence, a real button, the URL beneath it as a fallback, and a footer that says why this arrived. Nothing that fails in Outlook.

Costs: every change has to be made twice — the text and the HTML have to keep saying the same thing, and nothing enforces that. It is also the most email-specific code in the repo: inline styles, no stylesheet, a light background whatever the reader's theme.

The mark is a hosted PNG, and the wordmark beside it is TEXT. Email rules out the app's real logo: it is an SVG drawn in currentColor behind a mask, and Gmail strips SVG outright — a data: URI is stripped too. So the email uses icon-192.png, which the app already serves, at the origin it already knows.

Most clients block remote images until the reader allows them, which is the second frame. The mark carries alt="" — decorative, not named — because the word beside it is the name; an alt="bandplate" would read "bandplate bandplate" once images loaded, and say it twice to a screen reader.

Light, not branded dark. A dark-background email is a rendering minefield: Gmail and Outlook both invert colours in dark mode by rules you do not control, and the result is frequently unreadable. White is the one background that renders the same everywhere.

Georgia for the wordmark, not the app's Zilla Slab — email cannot rely on a web font, and Georgia is on effectively every machine. It reads as a serif wordmark, which is the point of it.

The button is a real link with padding, not an image and not a table-in-a-table. The URL is still printed underneath, because a button that does not render leaves nothing to click.
