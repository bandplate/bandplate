A real 1px rule at 60% cap-height in the border token — not a glyph. It sits at a fixed height regardless of the font, takes the theme's border colour, and can be hidden at narrow widths without touching the text.
One more element per field. Worth it: this is the only option where the separator is a drawn object you control rather than a character you inherit.

No separator at all. Fields sit in a flex row with a 1.4em gap and lean on the mono's own even rhythm to group. The quietest possible answer.

Stop treating it as one line. The title keeps the left, and length and key become right-aligned columns with fixed widths — so the separator problem disappears, and the values line up down the list where they are actually compared.
Only works where rows are uniform. A take that is missing a key leaves a hole, which has to read as deliberate rather than broken.
Where I'd land
M4 in lists, M3 on detail pages. A list is where values get compared, so columns earn their keep and the separator question stops existing; a detail page has room for labels and only one row to label. M1 is the right fallback wherever a line genuinely has to stay inline — a breadcrumb, a player subtitle — because it is the only option that keeps the separator under the theme's control instead of the font's. M2 is the one to avoid: it looks restrained but degrades the moment a fourth field appears.
