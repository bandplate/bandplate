Take row
One row, six places
Yes — it is one component. TakeRow.astro renders on the home page, search, a song's takes, /me and event detail, in three context modes. Not one of the six opts out of the vote control, and nothing hides it once a take is already a keeper — which is most of what looks wrong here. The row is not badly designed so much as undifferentiated.
Fixed regardless of which variant wins
The row is not a link. Only the title navigates, padded to a 44px target instead of stretching an overlay across everything.

Play is a filled gold plate — the mark's own shape, and the one place the accent belongs in a list. Unplayable takes keep the hairline ring.
The note is separated from the instruments by a hairline rule, not a space, and dropped to 82% opacity — it was reading as loud as the title.

The tally is gone. "2 of 2 votes say keeper (100%)" is a sentence nobody scans, on every row.
A keeper shows no vote control. The decision is made; the badge says so. Same for rejected. Voting appears only where the take is still open.

That alone removes the control from roughly half the seeded takes — five keepers and three rejected out of eighteen.

State on the row, actions one tap away in an overflow — vote, favourite, open the event. Nothing competes with the title, and the row gains room for actions that do not fit today.
An overflow menu hides what it holds; voting stops being something you notice you can do. It also needs real menu behaviour — focus trap, Escape, arrow keys — which the app does not have yet.
Where I'd land
V2. The question "is this row generic" answers it: six call sites, two of which are places anyone votes. Putting the control on all six was the mistake, not its styling — and a row that carries state only is the same row everywhere, which is what makes it safe to be generic. V1 is the smaller step if you want voting to stay one tap away from a list.
What it costs to build
V2 needs a prop on the row — the trailing slot already exists for exactly this, so the five pages that should not show voting pass an empty one and event detail keeps it. No new component, no fork. V3 would need a real menu (focus trap, Escape, arrow keys), which the app has nowhere yet.
