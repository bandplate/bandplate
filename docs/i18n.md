# Languages

bandplate ships English and Czech. A member picks theirs on `/me`; anyone
without a session gets what their browser asks for.

## Where the words are

Everything the app says lives in `packages/i18n`, one file per language per
area:

```
packages/i18n/src/messages/
  <area>.ts          both languages, on one import path
  en/<area>.ts       the SHAPE — every other language is checked against it
  cs/<area>.ts       the translation, with the English on each line
```

The areas are `common`, `shell`, `auth`, `home`, `songs`, `events`, `takes`,
`me`, `admin`, `mail`, `validation`, and four for the islands (`player`,
`voting`, `islands`).

**A page reads the whole catalog**: `const t = messages(Astro.locals.locale)`,
then `t.songs.title`. **An island reads only its own area** —
`playerMessages(locale)`, `islandsMessages(locale)` — because a `client:load`
island ships its imports to the browser, and the player is on every page.

## Adding or changing a string

1. Add it to `en/<area>.ts`.
2. `pnpm typecheck` fails until `cs/<area>.ts` has it too, because each Czech
   file is declared `satisfies typeof enArea`. A missing key, an extra key, or
   a function whose arguments have drifted is a compile error.
3. Put the English on the Czech line as a trailing comment. That is what makes
   the file reviewable on its own.

To **proofread the Czech**, read `cs/*.ts` top to bottom and edit in place —
the edit is the fix, there is no second copy to keep in step. Each file opens
with a box naming the glossary decisions it depends on and anything worth a
second opinion.

## Plurals, and why entries are sometimes functions

An entry is a plain string unless it interpolates or counts. When it counts, it
is a function, because **Czech does not have two plural forms**. It has four
CLDR categories, and the fourth is also the genitive that a numeral governs:

```
1 nahrávka   one     2–4 nahrávky   few
1,5 nahrávky many    5+ nahrávek    other
```

That is one axis, not two, so a per-noun record keyed by category covers both:

```ts
plural("cs", n, { one: "nahrávka", few: "nahrávky", many: "nahrávky", other: "nahrávek" })
```

**Put the whole clause in the record when more than the noun agrees.** Czech
verbs, possessives and adjectives agree with the count as well, and assembling
a sentence from a translated noun dropped into a fixed English frame produces
things like *"Jejích 2 nahrávky zůstává"* — wrong twice over. `cs/songs.ts`'s
`archiveConsequence` is the worked example.

A function is also what lets a translator **restructure**. Some sentences
cannot be translated in place at all: the vote tally reads "Držák: 3 z 5
hlasů" rather than mirroring the English word order, because the literal shape
drags a count-agreeing verb into a phrase whose noun is already genitive.

## How a request gets its language

In order, strongest intent first:

1. the signed-in member's `members.locale`
2. the `bp_locale` cookie, recording an earlier choice
3. `Accept-Language`
4. English

Resolved once in `apps/web/src/middleware.ts` and put on `Astro.locals.locale`.
The member's row is read on every request anyway (`resolveSession` loads it to
check `status`), so a language change takes effect immediately on every device
with no session revocation.

`bp_locale` is written whenever it disagrees with the member, so the sign-in
page after a logout is in the language they chose. It is **not** httpOnly (a
display preference, not a credential) and **not** cleared on logout — clearing
it is the bug it exists to prevent.

## Islands

Two rules, both learned the hard way:

- **Read the locale at call time**, from `document.documentElement.lang`, via
  `client/locale.ts`. `Player`, `VoteFavorite` and `ConfirmDialog` are
  `transition:persist`: Astro MOVES them between pages instead of remounting,
  so anything captured at hydration goes stale.
- **Pass `locale` as a prop as well.** A `client:load` island renders on the
  server, where there is no `document` — and Preact's `hydrate()` does not
  patch an attribute whose value differs, so an English server pass STICKS.
  The prop is the fallback; the live `lang` still wins in the browser.

Code that only runs after a click (XHR handlers, delegated listeners) needs no
fallback, and passing one there would only drag `locale` into dependency
arrays.

## Validation

Zod schemas are module-level constants built before any request exists, so they
cannot take a locale. They carry a **key** — `.min(1, "titleRequired")` — and
the page resolves it with `validationMessage(locale, key)`.

An unknown key is returned unchanged, so a key nobody added renders as itself:
findable, rather than a blank space under an input.

## Adding a third language

1. Add it to `LOCALES` in `packages/i18n/src/locale.ts` and give it a BCP 47
   tag in `INTL_TAGS`.
2. Add the column value: `members.locale`'s enum is spelled out in
   `packages/db/src/schema/sqlite/index.ts` (drizzle-kit cannot import the
   package), with a migration. `schema/locale.test.ts` fails until they agree.
3. Copy `messages/en/` to `messages/<new>/` and translate. Typecheck tells you
   what is missing; `messages/parity.test.ts` tells you what is still English.
4. Add it to each `messages/<area>.ts` registry.

The `/me` picker and the `Accept-Language` negotiation both read `LOCALES` and
need no change.

## What is NOT translated, and why

- **Instrument labels and event kinds.** They are admin-editable database rows,
  not code — a Czech deployment seeds Czech labels. A `label_cs` column would
  duplicate the admin UI, every read path and every fallback rule for a band
  that speaks one language.
- **Ingest API error bodies** (`packages/api/src/routes/ingest/*`). A machine
  contract with a published OpenAPI document. The one place a server message
  reaches a human is the uploader, which maps error *codes* to catalog entries.
- **Bare HTTP status bodies** — `new Response("Not found.", { status: 404 })`
  and the origin-check 403. No layout, no styling, reached only by a URL naming
  something that does not exist.
- **`formatTimestamp`** in admin tables. `en-CA` is how it gets `yyyy-mm-dd`;
  that is a technical format in a mono column, not a language.
- **Czech collation.** Ordering is `ORDER BY` in SQLite with `LIMIT/OFFSET`, so
  `Intl.Collator("cs")` cannot be applied without breaking pagination. Czech
  sorts `č` after `c` and `ch` after `h`, so lists will look mis-sorted to a
  Czech reader. Known, and out of scope.

## One consequence to know about

**Changing language stops playback.** The picker forces a full document load
(`data-astro-reload`), because a persisted island's already-rendered DOM cannot
re-translate itself. The control says so rather than letting it be discovered.

## Tests

| Test | Catches |
|---|---|
| `pnpm typecheck` | a missing, extra or wrong-arity key in any `cs` file |
| `messages/parity.test.ts` | a `cs` entry that is still the English string — walks every leaf, invokes function entries against fixtures, with an explicit allowlist for words that are genuinely identical |
| `barrel-is-workers-safe.test.ts` | an area growing past its byte budget, or the package gaining a dependency |
| `home-search-me-takes.route.test.ts` → "rendering in Czech" | the whole stack against the BUILT server: negotiation, precedence, `<html lang>`, the shell, and pages rendering Czech with no English left |

The route test asserts in **pairs** — something Czech present, a distinctive
English string absent. Positive alone passes a page rendering both; negative
alone passes a blank page.
